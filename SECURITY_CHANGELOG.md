# Security changelog

## Unreleased

### Critical — B2B replay protection

`order_id` was previously log-only, so the same order could be paid repeatedly.
`b2b_pay` now requires `payment_id = SHA-256(order_id)` and initializes an
immutable receipt PDA derived from agent, merchant, and payment ID. A duplicate
payment cannot initialize the same account and reverts atomically. The receipt
and `B2bPaymentSettled` event expose the exact split for indexers and HTTP 402
receipt verification.

### Critical — reachable passport lifecycle

Passports were minted `ACTIVE`, while `b2b_pay` required `VERIFIED_B2B`; no
instruction could perform that transition. The admin can now set only a known
passport status, and the merchant registry now has an admin-controlled
activation switch for incident response.

### High — invalid identities and dust royalty

Initialization rejects a zero treasury, passport minting rejects a zero IP
creator, merchant registration rejects a zero wallet, and B2B settlement
requires a non-zero 1 bp creator amount. These checks prevent unusable
configuration and make the documented atomic split true after integer rounding.

### High — checked oracle normalization

Pyth's exponent adjustment used unchecked addition, negation, and `u128::pow`.
An extreme feed exponent could panic the program instead of returning a
defined protocol error. The conversion now uses checked integer operations
throughout and has regression tests for normal negative/positive exponents,
fractional SOL, non-positive prices, and overflow boundaries.

### High — accounting panics and silent saturation

All reachable `unwrap()` calls in balance/accounting updates and all
`saturating_sub()` fee calculations were replaced with `MathOverflow` errors.
Failures now revert with a protocol error instead of panicking or silently
changing the credited amount.

### Supply chain — direct dependency pins

Anchor and Pyth direct dependencies now use exact versions rather than Cargo's
default compatible-version ranges. A transitive `Cargo.lock` still needs to be
generated by a trusted Rust toolchain and committed before a reproducible
release build. CI follows Pyth's documented remediation by forcing the
transitive Anchor 1.1.2 selection back to the program's 0.32.1, tests with
`--locked`, and publishes the resulting lockfile for review.
